lj-api

Serverless API for the Landjourney assignment. There is nothing to see at the root; the routes live under /api.

  • GET /api/health - liveness, environment and commit
  • POST /api/transition - move a workflow state machine

Reads go straight to Supabase under row-level security. Writes that move a state machine come here, because a transition has to be adjudicated somewhere the client cannot lie.

POST /api/transition

Requires Authorization: Bearer <supabase access token>. The actor's role is read from their profile, server-side; a role in the body is not carried past the parser.

{
  "machine": "application",
  "subjectId": "<uuid>",
  "event": "request_docs",
  "expectedRevision": 3
}

200 answers with ok, machine, subjectId, event, from, to, revision, actorRole, effects and the subject's events. Every other status answers with ok: false, a code, a reason, a blockers list of rule results, and the subject's current state and revision where they are known.

StatuscodeMeans
400invalid_requestThe body, machine, event, subject id or revision did not parse.
401unauthenticatedNo bearer token, or one the auth server does not recognise.
403no_profileAuthenticated, but with no profile row and therefore no role.
403role_not_permittedThe transition exists, but not for this actor's role.
404subject_not_foundNo such subject, or none this caller could have read.
409state_conflictNothing leaves the subject's current state on that event.
409revision_conflictThe subject moved under the caller. Refetch and retry.
422guard_refusedA guard said no. blockers says why.
500event_log_write_failedThe state moved but its audit entry did not land.
501machine_not_persistedA real machine whose subjects have no table yet.
501effect_not_implementedThe transition declares an effect this API cannot carry out.
